# Product Requirements Document (PRD): 스크롤링 포토 갤러리 웹앱

## 1. 프로젝트 개요 (Overview)
사용자가 사진을 이름과 함께 업로드하고, 위아래로 스크롤하며 자유롭게 감상할 수 있는 웹 기반 갤러리 애플리케이션입니다. 검색창에 특정 사진의 이름을 입력하면 해당 사진의 위치로 화면이 자동 이동하는 기능을 핵심으로 합니다.

## 2. 주요 기능 (Core Features)

### 2.1 사진 업로드 기능 (Photo Upload)
- 사용자는 자신의 디바이스에서 사진 파일(JPG, PNG 등)을 선택하여 앱에 업로드할 수 있습니다.
- 사진을 업로드할 때 반드시 **이름(제목)**을 입력해야 합니다.

### 2.2 스크롤 뷰 / 갤러리 (Scroll View)
- 업로드된 모든 사진이 앱의 메인 화면에 세로(또는 그리드) 형태로 표시됩니다.
- 마우스나 터치 스크롤을 이용해 편하게 사진을 감상할 수 있습니다.
- 각 사진 근처에 지정된 이름이 함께 표시됩니다.

### 2.3 검색 및 자동 이동 기능 (Search & Scroll Navigation)
- 화면 상단에 고정(Sticky)된 검색바를 제공합니다.
- 사진의 이름을 검색하면, 부드러운 애니메이션(Smooth Scroll)과 함께 해당 사진이 있는 위치로 화면이 즉시 이동합니다.

## 3. 화면 구성 및 사용자 경험 제안 (UI/UX Draft)
1. **헤더 영역 (상단 고정):** 
   - 갤러리 앱 로고 / 타이틀
   - 검색창 (돋보기 아이콘, 입력 텍스트)
   - 사진 추가 버튼 (+)
2. **메인 영역 (스크롤):**
   - 업로드된 사진 목록
   - 깔끔하고 감각적인 디자인 요소 (그림자 효과, 여백 등)
3. **업로드 모달(팝업):**
   - 이미지 미리보기 영역
   - 사진 이름 입력 텍스트박스
   - 완료 및 취소 버튼

## 4. 구현을 위한 기술 제안 (Technical Consideration)
- **프론트엔드 (UI):** 웹 표준 기술인 HTML, CSS, JavaScript 만으로도 충분히 구현 가능합니다. 최신 CSS (Flexbox/Grid, Sticky)와 바닐라 자바스크립트를 사용하면 빠르고 가볍게 개발할 수 있습니다.
- **데이터 저장소 (Storage):**
  - **옵션 A (브라우저 로컬 저장소 - IndexedDB 등 사용):** 별도의 백엔드 데이터베이스 없이 사용자 기기의 공간을 활용합니다. 개인용도로 사용하기 좋으며, 서버 지식이나 호스팅 비용이 들지 않습니다. 앱을 새로고침해도 사진과 이름이 유지됩니다.
  - **옵션 B (서버 구축 또는 Firebase 사용):** 다른 사람과 사진을 공유하거나 스마트폰, 데스크톱 여러 기기 환경에서 동기화가 필요할 때 사용합니다.

## 5. 완벽한 기획을 위해 논의가 필요한 사항 (Open Questions)

*이 부분은 함께 의견을 나누면서 구체화해 나갈 영역입니다.*

1. **데이터 저장 방식:** 위에서 제안한 A안(무료, 나만의 로컬 갤러리)과 B안(서버/DB 연동, 여러 기기 접속 가능) 중 어느 쪽이 적합하신가요?
2. **갤러리 디자인 방식:** 한 장의 사진이 인스타그램처럼 스마트폰 화면에 꽉 차게 나오는 '리스트 뷰'가 좋을까요, 아니면 핀터레스트처럼 크고 작은 사진들이 블록처럼 이어지는 '그리드 뷰'가 좋을까요?
3. **중복 이름 검색:** 만약 같은 이름의 사진이 여러 개 있다면(예: '여행사진1' 이 두 장일 경우) 어떻게 동작하길 원하시나요? (예: 일치하는 맨 처음 사진으로 이동, 혹은 이름이 같은 사진들만 따로 모아서 보여주기 등)
